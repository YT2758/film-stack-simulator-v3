# 正式站回歸與修正紀錄

測試起點：正式站 commit `25ea3ca`。既有 10 項瀏覽器測試全數通過，但新增故障情境證實仍有下列問題。測試均使用隔離瀏覽器資料，不清除使用者的正式瀏覽器草稿。

## 已確認根因與修正

| 問題 | 根因與修正 |
| --- | --- |
| 3D 切換語言後整片單色，仍顯示 Ready | 語言是 renderer／worker effect 依賴，但 camera 已定位旗標跨實例保留。語言改為即時翻譯狀態，camera 定位綁定 renderer 實例。 |
| 3D 重試不能恢復 worker 或有效畫面 | 重試現在重建 renderer 與 worker、重新定位；捕捉 worker 建立／執行／傳訊錯誤，過期首幀不得回寫 Ready。 |
| 版圖拖曳位置偏移 | 方形 viewBox 在寬容器置中留白，舊程式直接用容器 rect 正規化。實測拖到 X=10% 時，桌面變成 19.288%、手機變成 19.282%。改用 inverse SVG screen CTM 後，畫面與 JSON 均為 10%。 |
| 窄剖面點選位置錯誤與刻度疊字 | 繪圖尺寸被強制放大至至少 320px，和 CSS／指標座標不一致。改用實際畫布尺寸；nm 單位移到獨立上方位置。 |
| 儲存被封鎖時空白或一直 checking | localStorage 存取與初始 IndexedDB rejection 未妥善處理。偏好儲存失敗不阻止操作；草稿讀取失敗顯示已停止儲存。 |
| 損壞草稿被視為不存在 | envelope 驗證失敗回傳 null，讀取例外也被吞掉。現在只有 IndexedDB 真正缺值才視為無草稿，損壞內容保留且停用自動儲存。 |
| 初始／外部流程誤顯示已儲存或待儲存 | 新增尚未儲存狀態；未編輯範例／分享內容不會悄悄取代既有草稿。 |
| 草稿恢復、匯入、離頁可能遺失工作 | 恢復對話框期間背景 inert；Start fresh 未編輯時保留舊草稿；匯入／開啟具名堆疊前確認；pending／saving／錯誤／衝突的已編輯工作有原生離頁提示。讀取較新草稿後才詢問取代，並停止播放、清除舊分享網址。 |
| 具名堆疊操作失敗無提示 | 儲存／重新命名／刪除均捕捉例外，讀取失敗不顯示假空清單；寫入中防重複提交，已完成寫入與隨後清單讀取失敗分開呈現。 |
| 過大分享連結無回饋 | 捕捉編碼失敗並提示匯出 JSON；編碼端也遵守解碼端 5 MB 上限，避免產生自身無法還原的連結。 |

## 修改檔案

- `src/App.tsx`、`src/persistence/indexed-db.ts`、`src/persistence/share-codec.ts`：草稿生命週期、取代／離頁保護、分享錯誤。
- `src/components/ThreeViewer.tsx`：3D 資源、首幀與錯誤恢復。
- `src/components/LayoutEditor.tsx`、`CrossSectionCanvas.tsx`：座標與畫布一致性。
- `src/components/StackLibrary.tsx`、`src/i18n.ts`：真實儲存狀態、正體中文與英文訊息。
- `e2e/*-regression.spec.ts`：20 項新增回歸；`tests/codec.test.ts`：分享限制。
- `playwright.config.ts`：支援以 `PLAYWRIGHT_BASE_URL` 對已部署版本跑同一套測試。
- `scripts/run-egress.mjs`：因新增取代確認，測試明確接受確認，再驗證還原結果。

## 相容性與未驗證事項

- JSON／分享連結仍為 schema v3，無新套件、後端或追蹤。
- 舊 raw v3 IndexedDB 草稿讀取時不重寫，首次有意編輯後才遷移至既有 revision envelope。損壞草稿保留原值，不自動刪除或重設。
- 本次改善幾何操作可靠性，不宣稱製程物理準確度。
- 實體 iPhone／Android、Safari／Firefox、不同 GPU／驅動重設尚未測試。人工驗收：旋轉／縮放 3D、切換 EN／繁中、切面拖曳、PNG 與畫面一致；手機連續拖曳版圖後捲動頁面不應持續移動頂點。
- 原生離頁提示取決於瀏覽器規則，尤其手機強制關閉不保證觸發；儲存失敗時仍須匯出 JSON。
- 第三階段的明顯範例入口、數值版圖編輯、SADP 教學展開仍待後续產品工作，本次沒有列為完成。

- 正式網域與部署專屬網址均提供新版資產；主程式、codec、CSS 與本機 release build 逐位元組一致。
- 正式站再跑同一套 Playwright：**30/30 通過、無 skip**（約 1.1 分鐘）。另以一般 Chrome 目視確認 ARDE 3D 和未編輯範例的尚未儲存狀態。
- **正式 runtime 零外送檢查未通過**：測試 Chrome 收到不在 dist 中的額外同源腳本／樣式，以及由額外腳本發出的 HEAD／GET／POST 嘗試。未放寬白名單，也未關閉安全功能。
- 唯讀檢查：一般 Node HTTP 的 HTML 無額外腳本，隔離且禁用擴充套件的 Chrome 收到額外 parser 腳本，CDP initiator 將額外請求指向該腳本；沒有 service worker。Pages 專案的 Web Analytics tag/token 均未啟用。這些證據不足以確定注入者，不能斷言是 Cloudflare 或使用者瀏覽器，也未證實有流程資料傳出。
- 下一個具體任務：從另一台裝置／網路比對最初文件回應與額外腳本來源，釐清傳輸或瀏覽器環境差異後，重新跑嚴格正式零外送檢查。不要將尚未確認的環境行為硬改為應用問題。
